Incohérences corrigées

Trois contradictions entre la documentation et le code, repérées lors du premier audit et traitées depuis.

✓

La documentation décrivait une brique inexistante

ARCHITECTURE.md présentait une tâche planifiée @Scheduled de purge, absente du code. Elle est désormais explicitement signalée comme évolution hors MVP, dans le tableau des briques comme dans le diagramme.

✓

Le README décrivait un projet qui n'existait plus

Il annonçait « implémentation à venir » et tous ses liens pointaient vers un dossier docs/ renommé depuis. Entièrement réécrit.

✓

Le contrat d'interface décrivait une API différente du code

Découvert en rédigeant ce rapport : openapi.yaml annonçait un objet utilisateur en réponse à l'inscription (le code renvoie un corps vide), un AuthResponse imbriquant un user (le code l'aplatit en userId et email), et un format d'erreur avec des champs error et path qui n'existent plus. Les trois sont réalignés.

Ce qu'il reste à faire

Cinq points partiels et un point à trancher. Aucun n'est bloquant pour le dépôt : tous sont documentés comme limites assumées.

1

Confronter les écrans aux maquettes

Le seul point que je ne peux pas vérifier : les maquettes ne sont pas dans le dépôt. Compare-les toi-même, et ajoute-les au repo — un évaluateur ne peut pas juger la conformité sans référence.

2

Renforcer le responsive

Deux @media pour toute l'application, dans Layout et FileRow. Teste les écrans en largeur mobile et ajoute les points de rupture manquants, notamment sur les formulaires et le tableau des fichiers.

3

Formaliser l'accessibilité

21 attributs ARIA constituent une base saine, mais aucun audit n'est tracé. Un rapport Lighthouse et un parcours complet au clavier fourniront des preuves citables en soutenance.

4

Compléter les scripts de déploiement

docker-compose.yml ne lance que PostgreSQL. Un Dockerfile pour le back et un service supplémentaire dans le compose rendraient le projet déployable en une commande.

5

Passer de la mesure à l'optimisation

PERF.md caractérise l'existant mais n'améliore rien. La piste la plus défendable : découper le bundle avec React.lazy sur la page publique de téléchargement, seule page vue par des visiteurs sans compte.

6

Commiter l'ensemble

Une vingtaine de fichiers créés ou modifiés attendent d'être versionnés. Rien de tout ce travail ne comptera s'il ne figure pas dans le dépôt remis.
